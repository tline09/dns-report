DNS-Report

A PowerShell tool that generates a clear DNS, email and WHOIS report as HTML for any domain — ideal for quick domain and security checks.

What the report shows

DNS records

Name servers, A/AAAA, MX, TXT and SOA — the technical basis of the domain.

Email security

SPF, DMARC and DKIM including an assessment of whether protection is strict enough.

Website & SSL

Availability of the site and expiry date of the SSL certificate.

WHOIS / RDAP

Registrar, registration and expiry date, status and DNSSEC.

Overall score

A score per domain with concrete, prioritized recommendations.

Printable as PDF

Clean layout for printing or PDF export straight from the browser.

Quick start

Download the script and run it in PowerShell:

# Check a domain and open the report immediately
.\DNS-Report.ps1 -Domain example.ch -Open

# Multiple domains in one combined report
.\DNS-Report.ps1 -Domain "example.ch","example.com"

# Query via a public DNS server
.\DNS-Report.ps1 -Domain example.ch -DnsServer 1.1.1.1

The report is created as an HTML file in the same folder. In the browser it can be saved as PDF with Ctrl + P.

Note: When exporting to PDF, enable "Background graphics" in the print dialog so the colors are kept.

Parameters

ParameterDescriptionDefault
-DomainOne or more domains (comma-separated, no spaces).example.ch
-OpenOpens the report in the browser after creation.(off)
-DnsServerDNS server for all queries. Empty = system default.1.1.1.1

Note on corporate networks (split DNS)

In networks with their own Active Directory DNS, an internal zone may answer the same domain differently than the public internet. Therefore the script queries via 1.1.1.1 by default to show the public view. For internal zones an internal server can be set via -DnsServer.

Understanding SPF, DKIM, DMARC & DNSSEC

The four security features the report evaluates:

  • SPF — defines which servers may send email on behalf of the domain (the "guest list").
  • DKIM — adds a digital signature to every email that proves authenticity and integrity.
  • DMARC — determines what happens to emails that fail SPF or DKIM (none / quarantine / reject).
  • DNSSEC — signs the DNS response itself and thus protects against manipulated DNS answers.
